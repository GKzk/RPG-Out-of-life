# OUT OF LIFE — БАЛАНС ЧИСЛОВОЙ МОДЕЛИ SKILL CHECK

> Версия 1.0, 25.09.2026.
> Статус: рабочая математическая модель, утверждаемая для дальнейшего прототипирования.
> Модель протестирована симуляцией до переноса в игровой код.

## 1. Цель модели

Система должна одновременно обеспечить:

- различие между характеристикой и навыком;
- заметное влияние обучения;
- заметное, но не доминирующее влияние природной способности;
- ограниченную случайность;
- отсутствие модели «навык = процент успеха»;
- пять исходов проверки;
- возможность почти гарантированного выполнения простых задач;
- возможность выполнить очень сложную задачу только при соответствующей компетенции, подготовке и/или удаче;
- отсутствие универсальной характеристики или навыка.

## 2. Базовый числовой диапазон

Характеристики:

- 1–10.

Навыки:

- 0–100.

### 2.1. Вклад характеристики

**Attribute Contribution = Attribute × 4**

Диапазон:

- 1 → 4
- 5 → 20
- 10 → 40

### 2.2. Вклад навыка

**Skill Contribution = Skill × 0.6**

Диапазон:

- 0 → 0
- 50 → 30
- 100 → 60

Таким образом максимальный базовый показатель персонажа без внешних факторов:

**40 + 60 = 100**

Это намеренно делает 100 навыка не «100% успеха», а верхней точкой компетентности.

## 3. Базовая формула

До броска:

**Base Score = Attribute × 4 + Skill × 0.6**

После применения внешних факторов:

**Final Score = Base Score + Equipment + State + Context + Preparation + Roll**

где:

- Equipment — модификатор экипировки;
- State — влияние текущего состояния;
- Context — общая оценка ситуации;
- Preparation — преимущество от подготовки;
- Roll — случайный результат.

## 4. Случайность

Используется **1d20**.

Для расчёта:

**Roll Modifier = d20 − 10**

Диапазон:

**−9 ... +10**

Это ограниченная случайность, а не процентный бросок.

Разница между двумя соседними значениями составляет 1 пункт.

## 5. Сложности

Фиксируются следующие базовые значения:

| Класс | Difficulty | Назначение |
|---|---:|---|
| Очень низкая | 20 | простая задача с минимальным риском |
| Низкая | 35 | доступная задача для подготовленного персонажа |
| Средняя | 50 | нормальная профессиональная задача |
| Высокая | 65 | сложная профессиональная задача |
| Очень высокая | 80 | редкая/опасная задача |
| Экстремальная | 100 | предел человеческой компетентности |

Это не означает, что каждое действие обязано использовать ровно одно из этих значений. Между ними допустимы промежуточные сложности.

## 6. Расчёт результата

**Margin = Final Score − Difficulty**

Базовые диапазоны:

| Margin | Результат |
|---:|---|
| ≥ 0 | Успех |
| −1 ... −9 | Частичный успех |
| −10 ... −19 | Провал |
| ≤ −20 | Критический провал |

### 6.1. Критический успех

Естественный результат **20** превращает успешную проверку в критический успех.

Условия:

- действие действительно является проверкой;
- Margin ≥ 0;
- выпало естественное 20.

Критический успех не должен означать случайный огромный бонус. Он даёт заранее определённый дополнительный эффект конкретной задачи:

- экономия ресурса;
- дополнительная информация;
- более быстрый результат;
- улучшенное качество;
- дополнительная возможность.

### 6.2. Критический провал

Естественный результат **1** превращает провал в критический провал.

Условия:

- Margin < 0;
- выпала естественная 1.

Критический провал должен иметь конкретное причинно-следственное осложнение и не должен случайно уничтожать прохождение.

## 7. Автоматические результаты

Проверка не должна бросаться там, где риск отсутствует.

### Автоматический успех

Используется, если:

- задача тривиальна;
- нет значимого риска;
- компетентность персонажа делает исход очевидным;
- провал не создаёт интересного игрового решения.

Например, персонаж с Механикой 70 чинит обычный простой механизм в безопасных условиях.

### Автоматический провал

Используется, если:

- отсутствует обязательное условие;
- действие физически невозможно;
- персонаж не имеет доступа к необходимому типу действия;
- сюжетное/системное условие исключает попытку.

## 8. Порог навыка

Порог не заменяет проверку.

Он отвечает на вопрос:

> «Может ли персонаж вообще выполнять этот тип действия?»

Рабочая сетка порогов:

| Порог | Ориентир |
|---:|---|
| 20 | базовое специализированное действие |
| 40 | уверенное профессиональное действие |
| 60 | сложное специализированное действие |
| 80 | экспертное действие |

Порог применяется только там, где действительно существует качественный барьер.

Если порог не достигнут, игра должна по возможности предложить альтернативу:

- другой предмет;
- другой маршрут;
- помощь NPC;
- покупку услуги;
- другой навык;
- получение информации;
- подготовку;
- иной способ решения.

## 9. Внешние модификаторы

Модификаторы не должны превращать систему в сумму десятков мелких бонусов.

### Контекст

| Контекст | Modifier |
|---|---:|
| Благоприятный | +5 |
| Нейтральный | 0 |
| Неблагоприятный | −5 |
| Критически неблагоприятный | −10 |

### Подготовка

Обычно:

- нет подготовки: 0;
- хорошая подготовка: +5.

Более сильный эффект подготовки предпочтительно выражать через снижение Difficulty или изменение доступных действий, а не большим бонусом.

### Состояние

Состояние применяется только к связанным действиям.

Ориентир:

- лёгкое влияние: −5;
- тяжёлое влияние: −10.

Не существует универсального «−10 ко всем навыкам».

### Экипировка

Обычно:

- неподходящее оборудование: −5;
- подходящее: 0;
- специализированное: +5.

Но основной эффект предмета должен быть функциональным:

- открыть действие;
- снять ограничение;
- изменить последствия;
- сделать ранее невозможную процедуру доступной.

### Общий принцип

Суммарный внешний модификатор в обычной ситуации желательно удерживать примерно в диапазоне:

**−20 ... +15**

Большие значения должны быть редкими и объяснимыми.

## 10. Пример расчёта

Персонаж:

- INT 7;
- Механика 42;
- инструмент есть;
- нейтральный контекст;
- без подготовки;
- состояние нормальное.

Базовый показатель:

**7 × 4 + 42 × 0.6 = 28 + 25.2 = 53.2**

Для высокой сложности:

**53.2 − 65 = −11.8**

Затем добавляется результат d20−10.

Персонаж находится около границы между провалом и частичным успехом.

Это соответствует замыслу: задача доступна, но сложна.

## 11. Контрольные персонажи

Для математического тестирования использованы:

| ID | Профиль | Атрибут | Навык | Base Score |
|---|---|---:|---:|---:|
| A | Низкая способность / эксперт | 3 | 80 | 60 |
| B | Высокая способность / новичок | 8 | 20 | 44 |
| C | Средний специалист | 5 | 50 | 50 |
| D | Сильный специалист | 8 | 80 | 80 |
| E | Слабый новичок | 3 | 20 | 24 |
| F | Узкий мастер | 5 | 90 | 74 |

Эти персонажи являются тестовыми профилями, а не игровыми архетипами.

## 12. Результаты симуляции

Проведено по **30 000 бросков** для каждого сочетания персонажа и сложности.

Всего проверено:

**6 профилей × 6 сложностей × 30 000 = 1 080 000 бросков.**

### 12.1. Средний специалист — C

INT/аналогичная характеристика = 5, навык = 50, Base Score = 50.

При средней сложности 50:

- критический успех ≈ 5%;
- успех ≈ 45–50%;
- частичный успех ≈ 40–45%;
- провал ≈ 0%;
- критический провал ≈ 5%.

Это ожидаемое поведение для равного Base Score и Difficulty: персонаж часто достигает цели, но часть попыток имеет цену.

При высокой сложности 65:

- успех ≈ 0%;
- частичный успех ≈ 30%;
- провал ≈ 50%;
- критический провал ≈ 20%.

Следовательно, средний специалист не должен стабильно выполнять сложную профессиональную задачу без подготовки.

### 12.2. Низкая способность / эксперт — A

Атрибут = 3, навык = 80, Base Score = 60.

При высокой сложности 65:

- критический успех ≈ 5%;
- успех ≈ 25%;
- частичный успех ≈ 50%;
- провал ≈ 15%;
- критический провал ≈ 5%.

Это подтверждает важное свойство модели:

**высокий навык компенсирует слабую характеристику, но не отменяет её.**

### 12.3. Высокая способность / новичок — B

Атрибут = 8, навык = 20, Base Score = 44.

При средней сложности 50:

- критический успех ≈ 5%;
- успех ≈ 20%;
- частичный успех ≈ 50%;
- провал ≈ 20%;
- критический провал ≈ 5%.

Это подтверждает обратное:

**высокая характеристика помогает, но не превращает новичка в специалиста.**

### 12.4. Сильный специалист — D

Атрибут = 8, навык = 80, Base Score = 80.

При очень высокой сложности 80:

- критический успех ≈ 5%;
- успех ≈ 45–50%;
- частичный успех ≈ 40–45%;
- провал ≈ 0%;
- критический провал ≈ 5%.

Следовательно, сильный специалист способен регулярно работать на очень высокой сложности, но не получает автоматического успеха.

### 12.5. Узкий мастер — F

Атрибут = 5, навык = 90, Base Score = 74.

При очень высокой сложности 80:

- критический успех ≈ 5%;
- успех ≈ 20%;
- частичный успех ≈ 50%;
- провал ≈ 20%;
- критический провал ≈ 5%.

Это показывает, что даже навык 90 не является универсальным ключом: без соответствующей характеристики и/или подготовки экстремально сложные задачи остаются рискованными.

## 13. Проверка крайних случаев

### Навык 100 + характеристика 10

Base Score = 100.

На экстремальной сложности 100 персонаж находится около равенства с Difficulty.

Следовательно, мастер может выполнить задачу на пределе человеческой компетенции, но не получает абсолютной гарантии.

### Навык 0 + характеристика 10

Base Score = 40.

Высокая характеристика не превращает персонажа в обученного специалиста.

### Навык 100 + характеристика 1

Base Score = 64.

Эксперт с плохой природной способностью остаётся функциональным, но значительно хуже универсального мастера.

### Навык 0 + характеристика 1

Base Score = 4.

Для профессиональных задач такой персонаж практически не подходит без альтернативного решения.

## 14. Что модель подтверждает

Симуляция подтверждает следующие свойства:

1. Навык является главным источником профессиональной компетенции.
2. Характеристика существенно влияет на результат, но не заменяет навык.
3. Разница между новичком и экспертом большая.
4. Высокий навык не превращается в 100% вероятность.
5. Высокая характеристика не превращает низкий навык в высокий.
6. Сложность 50 является естественной точкой проверки для среднего специалиста.
7. Сложность 80 является рабочей зоной для сильных специалистов.
8. Сложность 100 соответствует верхнему человеческому пределу.
9. Внешние факторы способны заметно изменить результат без изменения постоянных характеристик.
10. Порог навыка и проверка могут существовать одновременно.

## 15. Что НЕ считается зафиксированным

Эта модель фиксирует математический каркас, но пока не фиксирует:

- конкретные пороги каждого игрового действия;
- конкретные значения Difficulty для сюжетных сцен;
- точные бонусы отдельных предметов;
- точные штрафы отдельных состояний;
- точные правила социальных проверок;
- конкретные эффекты критических результатов;
- баланс получения очков навыков;
- стоимость повышения навыка;
- стартовые значения навыков предысторий;
- взаимодействие перков с проверками.

Эти параметры должны балансироваться после появления реальных игровых действий.

## 16. Важное ограничение

Модель проверена математически на искусственных контрольных профилях. Это не доказательство окончательного игрового баланса.

Следующий этап — прототипировать реальные проверки из игры и проверить:

- бой;
- скрытность;
- медицину;
- механику;
- электронику;
- поиск;
- ориентирование;
- социальные действия;
- взрывчатку;
- действия с питомцем.

Если в реальных сценариях появится перекос, сначала корректируются Difficulty и внешние модификаторы, а не базовые коэффициенты всей системы.
